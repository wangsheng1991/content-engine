# 增长路线图 v1 — 技术资产 → 免费体验 → 社区 → 品牌直达

日期：2026-09-21　适用产品：`dlss5nvidia.com`、`houseplusplus.com`（渲见 RenVi）
配套引擎：`content-engine`（本仓库）　参考标的：wuli.art 的 `Wuli-art/*` HF 资产

---

## 0. 结论先行

1. **走技术资产驱动的路，不做内容站、不靠买量。**技术资产本身就是获客页：`Wuli-art/Qwen-Image-2512-Turbo-LoRA-2-Steps` 在 HF 上 22,413 次下载，model card 第一屏就是"来 wuli.art 免费试"。
2. **三个锚点分工明确**：Hugging Face 放模型/数据集/评测结果，GitHub 放代码/工作流/可复现脚本，产品站是**唯一转化终点**。
3. **每份资产必须带一个"立刻就能用"的入口，且落到预填参数的用例页**，绝不落首页。这是整条链最容易做错、也最影响转化的一环。
4. **先跑通一个最小闭环**（一个产品、一个场景、一份评测、一次发布），再谈节奏化。
5. **我们没有 wuli 的基座和算力，但有他们没有的三样东西**：真实任务、真实失败案例、多上游可选。这三样正好支撑「路由/编排」这一层自有技术资产。

---

## 1. 目标与北极星

**北极星指标：由技术资产与内容带来的「注册并完成首张出图」用户数。**
两个产品统一用这一个口径（RenVi 已有此定义，dlss5 沿用），播放/点赞/粉丝只作诊断。

三层诊断指标：

| 层 | 指标 | 数据来源 |
|---|---|---|
| 资产层 | HF 下载数 / likes、GitHub star / clone、被引用的外链数 | HF API、GitHub API、GSC 反向链接 |
| 站点层 | 自然搜索点击、Direct 占比、品牌词点击 | GSC、GA4 |
| 产品层 | 注册、首张出图、付费转化、首图获客成本 | Firebase / Stripe / PayPal |

> 付费上线前，最后一列暂时只有"注册 + 首图"。**支付是这条路的第一优先级**：没有付费，整条飞轮的最后一环是断的，只能优化到"首图"。

---

## 2. 飞轮（我们的版本）

```
热点模型 / 新技术出现
      ↓
评测 + 路由策略        ← 我们的自有技术增量（不是基座训练）
      ↓
Hugging Face 发布      ← 模型 / 数据集 / 评测结果（downloads 可验证）
      ↓
GitHub 发布            ← 可复现脚本 / 工作流 / 配置
      ↓
产品免费体验           ← 额度内直接出图，零部署
      ↓
社区放大               ← Reddit / HN / X / Linux.do / 小红书
      ↓
真实 prompt 与失败案例  ← 只有我们看得到
      ↓
评测 v2 / 场景 LoRA / 路由 v2
      └────────────→ 回到第二轮
```

铁律：**每一轮必须有可验证的指标**（成本、耗时、成功率）。wuli 的传播货币是"20x faster⚡️"，我们的必须是同量级的一句话，没有指标就没有传播。

## 3. 三个锚点的分工

| 锚点 | 放什么 | 为什么是它 | 第一屏必须有 |
|---|---|---|---|
| **Hugging Face** | 评测数据集、路由评测结果、场景 LoRA、prompt-extend 小模型 | 目标人群在这里找模型（wuli 的下载量证明）；有 downloads/likes 两个可验证的传播指标；全球可达 | 一句可验证结论 + "在线免费试"深链 |
| **GitHub** | 评测 harness、路由配置、ComfyUI/工作流、部署脚本、复现说明 | 代码的家；README 会被搜索引擎和 AI 语料长期抓取；star/issue 是社区触点 | badges + Quick start + 深链回产品 |
| **产品站** | 用例页（搜索/社交流量的落点）、免费额度、一键同款入口 | 唯一能完成转化（首图/付费）的地方 | 能立刻出图，不需要读文档 |
| **社区** | 技术帖（不是广告）、失败案例对比、版本更新 | 放大器，不承担转化，只承担"带来人" | 落到用例页的 UTM 链接 |

**内容站（博客）降级为辅助**：它承接长尾搜索，但不作为资产本体。真正承接通量的是"用例页 + 资产卡片"。

## 4. 导流机制：每个资产怎么把人送回产品

| 资产 | 回流入口 | 落点（必须） | 追踪键 | 转化事件 |
|---|---|---|---|---|
| HF 模型/数据集卡 | 正文第一屏 "Try it free" 深链 | 用例页 `?preset=<id>` | `utm_source=huggingface&utm_content=<asset_id>` | 注册 / 首图 |
| HF Space（Demo） | 生成结果旁的 CTA + 额度墙 | 产品内同款 | `space_id` | 首图 / 付费 |
| GitHub README | badge + Quick start 里的深链 | 用例页 `?preset=<id>` | `utm_source=github&utm_content=<repo>` | 注册 / 首图 |
| GitHub Release / 评测更新 | 更新日志里的"在线试" | 用例页 | 同上 | 注册 / 首图 |
| 用例页 | **一键同款**（预填参数） | 产品生成页 | `preset_id` | 首图 |
| 社区帖（Reddit/X/HN/小红书） | 帖子里的落地链接 | **用例页，不是首页** | `utm_campaign=<topic>` | 注册 / 首图 |
| 品牌直达 | 首页 | 首页 | GA4 Direct + GSC 品牌词 | 复用 |

三条硬规则：

1. **落点必须是"能立刻出图"的页面。**落首页是这条链上最常见的错误，转化会掉一个量级。
2. **每个资产一个唯一 `asset_id`**，贯穿 UTM、`preset_id` 与产品事件，这样才能回答"是哪份资产带来的这个用户"。对应地，内容引擎编译产物时自动带上追踪参数。
3. **免费额度是转化闸门，不是无限免费。**额度由付费用户补贴；每个免费首图都要记成本，超过阈值就收紧。

## 5. 路线图

### 阶段 0 · 定义与埋点（1 周）

- 定**品牌引擎名**（自有名字 + 一句可验证定位的模板：`<名字>：按任务自动选模型，成本 ↓X%、成功率 A→B`，数字待评测后填）。
- 打通追踪：`asset_id` → `preset_id` → 首图事件。dlss5 用 GA4 + Firebase，RenVi 用飞书回填 + 产品事件。
- 把现有的 HF/GitHub/社区动作列出清单，标注哪些已有、哪些没有。

**验收：能回答"上周哪 3 条内容各带来了几个首图"。**

### 阶段 1 · 第一个最小闭环（2 周）

选**一个产品 + 一个场景**，跑通一整圈：

1. 取 30 个**真实任务**（真实输入 + 真实 prompt）。
2. 评测 harness：3–5 组上游模型/参数 × 30 任务 → 成功率、耗时、单图成本、失败模式分类。harness 必须**可重跑**（模型会变，结论会过期）。
3. 路由 v0：按任务的策略表 + 成本上限 + 失败回退，直接接进产品。
4. 发布三件套：HF 数据集卡 + GitHub 仓库（脚本 + 路由配置）+ 3 个用例页（带一键同款）。
5. 1 篇社区稿：**重点发失败案例对比**（最有传播性的形态），附可复现脚本。

**验收：HF/GitHub 都有资产在线；从它们带来的注册 ≥ 5；用例页有真实转化数据（哪怕很小）。**

### 阶段 2 · 节奏化（2–4 周）

- 固定节奏：**每 2 周一轮**——新模型/新版本 → 评测 → 发布 → 内容。新模型上线就进路由候选，评测结果就是本期内容。
- 上第一版**场景 LoRA / prompt-extend**（团队训练能力在这里进场）。
- 建立发布 checklist，把可自动的部分交给 `content-engine` 编译 + 定时任务。

**验收：两轮不断档；Direct + 品牌词占比环比上升。**

### 阶段 3 · 规模化与分工（按数据决定）

- 用阶段 1–2 的数据决定：加码哪个渠道、砍掉哪个、哪里可以无人值守。
- 第二个产品复制同一套（先做哪个产品见第 10 节）。

## 6. 度量与复盘

每周一张表，三个数字必须在一起看：

| 排名 | 列 | 说明 |
|---|---|---|
| 1 | `asset_id` / 内容标题 | 唯一标识 |
| 2 | 资产层表现 | 下载/star/曝光 |
| 3 | 站点层表现 | 点击、Direct |
| 4 | **首图数** | 核心 |
| 5 | 首图成本 | 免费额度消耗 + 人力 |
| 6 | 决策 | 继续 / 加码 / 停产 |

规则：连续两周低于中位数的主题停产；前 20% 复制一组。**没有决策的复盘不算复盘。**

## 7. 自动化边界

| 环节 | 自动 | 人工 |
|---|---|---|
| 评测与路由 | ✅ 全自动 | 抽查异常 |
| HF / GitHub 发布 | ✅ 脚本 + 模板 | 首发内容审核 |
| 产品站/用例页 | ✅ 编译部署 | — |
| Bluesky / Pinterest / IG（官方 API） | ✅ 排程 | 首月盯回执 |
| Reddit / HN / Linux.do | ❌ 只做机会发现 | **全人工发布与互动** |
| 小红书 / 抖音 | 生成与同步自动 | **人工发布** |
| X | 草稿自动 | 人工确认 |

红线：不做自动建号、不伪装真人、不做未经请求的 outreach；自动发布平台连续失败 3 次即暂停。

---

## 8. 风险与红线

1. **传播讲准确话。**对技术人群必须说清是"编排多个开源模型的路由层"，评测集、脚本、失败案例一起发。被扒出"号称模型其实是 if-else"，信誉直接归零。
2. **输出一致性是路由的真实产品风险。**按场景固定模型家族、不在单次会话中跳模型，必要时加统一后处理，否则用户会觉得产品不稳定。
3. **上游依赖。**模型上下线会让 benchmark 过期 → harness 必须可重跑，结论标注日期与版本。
4. **免费额度成本**。设硬上限与告警，别让免费把毛利吃掉。
5. **平台合规**。Reddit 等平台的条款禁止自动化账户行为与未授权推广，遵守既有黑名单与 90/10 比例。
6. **不发布没有真增量的东西**。没有新模型/新版本时，评测与失败案例也是增量；纯转载不是。

## 9. 本周就能动的第一步

1. 列出两个产品**现有的多模型调用点**（dlss5: FAL `gpt-image-2/edit`、AlphaNet `flux-klein`；RenVi: FAL、通义万相），确认哪些已可切换。
2. 选一个场景，攒 30 个真实任务（真实输入 + prompt + 期望）。
3. 写评测 harness（先离线跑，不接产品），产出第一张"模型 × 任务"结果表。
4. 结果表 → 路由 v0 策略草稿 + 第一份可发布资产的大纲。
